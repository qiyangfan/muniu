# 语义缓存 v0 草案(semantic-cache)

> Phase 4 能力。本文为方向契约;实现前按当时实测将 ⚠ 项定稿,定稿即契约。

## 目标

同义问题命中缓存,省 token、降延迟。**宁缺勿错**:错误命中(语义相似但答案不同)对用户是事故,阈值与准入条件从保守起步。

## 缓存键与准入

- 键 = SHA256(归一化指纹):归一化 = messages 去空白抖动 + model_alias + tools 指纹 + `temperature≤0.3 ⚠`(高温不缓存)。
- **准入白名单**(同时满足才可缓存):无流式要求差异(流式命中可拼包回放,Phase 4 末开)· 响应正常结束(`finish_reason=stop`)· 无工具调用发生 · 非长上下文(输入 ≤8K tokens ⚠)· tenant 级开关(默认关)。
- 失效:TTL(默认 24h ⚠)+ LRU 容量上限;**不做主动失效**(上游知识更新不可感知,如实定位为「缓存的是相似问题的一次参考答案」,文档明示)。

## 检索管线

嵌入(租户自备 embedding key,经本网关 `/v1/embeddings` 通道 ⚠)→ 内存向量索引(启动时从 SQLite 加载)→ TopK=5 → cosine ≥ `0.97`(保守起步,实测校准)→ 返回命中并 `hits+1`。

向量索引选型(Phase 4 开工时定,候选与评估判据):

| 候选 | 性质 | 评估判据 |
|---|---|---|
| `github.com/coder/hnsw`(或同期维护最好的纯 Go HNSW)⚠ | 纯 Go,内存 | 1 万条 · Top5 · p99 < 10ms;失活则换 |
| 暴力余弦(排序遍历) | 零依赖 | 1 万条内实测 < 5ms 则直接用它——**规模不需要索引就不上索引** |

嵌入向量 BLOB 存 SQLite(1536 维 float32 ≈ 6KB/条),索引仅内存态,重启重建。

## 计量与可观测

命中行照记 `usage_logs`:`provider='semantic-cache'`,`cost_credits=0`,`cached_tokens=0`,命中延迟单独字段;控制台展示命中率/节省 token 数(Phase 4 控制台首屏图表)。

## Non-goals

不做缓存预热、不做跨租户共享、不做增量更新、不做分布式缓存(单二进制定位)。
