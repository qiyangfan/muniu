# ADR-0019:渠道上游健康观测与熔断降级归属网关

- 状态:已接受(2026-10-30;openspec `upstream-health-probing` 承载)

## 决策

上游渠道的**健康观测与熔断降级路由**是网关自保能力,归属本仓;不消费厂商官方状态页(自述滞后、多厂商覆盖不齐、组件映射人工,只可作运维情报不可作路由控制信号),自建多厂商探测。

1. **探针分两层**:免费控制面探针(`GET /models` 族,证网络/TLS/鉴权/服务在线,**零货币成本,持 key 渠道缺省全开**、渠道级 `free_probe: false` 退订、全局总闸);付费推理探针(最小补全 max_tokens 微值,证推理面——免费端点 200 不证推理面,厂商状态页按模型分 lane 统计即直接证据),**声明制**(`probe_model` 非空才启用),个人项目零付费、企业按需开。gemini 原生 v1 不具备探针端点形态,该族渠道跳过探针、被动统计照常(登记限制)。
2. **探针与 key 池完全解耦**:探针经装配期 key 快照取值,零触碰 Pick/Report(EMA/冷却/禁用零写入)——探针流量特性(固定微值/固定频率)会污染 EMA 统计;探针 429 判「存活但受限」不计成败,防止探针自身限频把活渠道打入降级。
3. **被动统计缺省开启(路由行为变化点)**:真实流量的渠道失败率越线 → 渠道级降级、候选域整路收缩。现状是 key 级 EMA 下限 0.1「防饿死漏拍」——全劣化渠道持续漏拍真实流量;本决策把恢复探测职责上移到半开机制(degraded 计时到期 → half-open 放行流量 → 下一真实请求裁决)。`health.enabled: false` 一键回退到现行为。
4. **恢复判据与降级原因同层对称**:控制面阴性由免费探针连续成功翻案(静默渠道的关键恢复路径);推理面阴性由付费探针成功翻案;被动阴性只由真实流量试探翻案(probe_model 与失败模型可能不同 lane,跨层解除是不诚实恢复)。半开期真实请求成功是全层证据,对任意原因均可恢复。
5. **单候选渠道快速失败**:降级期 503 `provider_circuit_open` 信封,零上游调用、零计量行;多候选别名透明切换,用户无感。切换率越线(窗口换道率 ≥ 阈值,最低样本门槛)发统计告警,补「部分劣化零告警」缺口(`all_candidates_failed` 只抓彻底失败)。

## 理由

- **静默渠道之死无人知晓**:现状只有真实流量的第一次失败才发现上游故障,损失由用户请求承担;免费控制面探针以零成本把发现提前到故障后的一个探针周期。
- **真实流量是最好的探针**:被动统计零成本且信号最真实;主动探针只补「零流量渠道」的真空档,故免费层缺省开、付费层声明制——不为个人项目的零成本诉求牺牲企业用户的推理面可见性。
- **探测管线不引外部依赖**:探针即 stdlib HTTP(与余额查询同纪律),不消费厂商 SDK、不依赖状态页 feed;告警复用 webhook-alerting 管道,事件经 Notifier 外发。
- **诚实边界**:probe_model 与真实流量模型不同 lane 的健康差异是已知限制(文档建议配置一致);健康态为进程内存态,重启重置并由首轮探针校准(短生命周期信号,持久化复杂度大于价值)。
