# ADR-0007:可插拔计量汇与本地缓冲续传

- 状态:已接受(2026-09-11)
- 依据:ADR-0005(数据面双形态)

## 决策

计量管道落库端抽象为**汇(Sink)**,三种实现:①本地 SQLite(standalone 默认,现状行为);②控制面 ingest(cluster 主路径,HTTP 批量投递);③直写 PostgreSQL(cluster 可选,依赖白名单 ADR 增补后才允许实现)。硬契约:

- **计量行绝不丢**:ingest 投递失败 → 整批落本地 SQLite 缓冲表;恢复后按序续传,以行主键幂等去重;缓冲超容量上限时**阻塞消费**(背压沿 channel 传导至请求路径)并持续告警——与「计量行是钱」契约一致;
- 本地 SQLite 缓冲文件必须可独立对账(对账兜底);
- standalone(汇=本地)行为与现状逐字节等价,缓冲路径完全不启用。

## 理由

- 汇接口是形态 A/B 唯一的存储分叉点——把「是否切 PG」隔离在汇实现层(ADR-0005 裁决:控制面切 PG,muniu 不切默认依赖);
- 缓冲续传复用 SQLite 的可靠性(断网期间网关仍全速转发,计量在本地落盘),避免为推送引入消息队列这类重依赖(依赖纪律)。

## 备选与否决

- Kafka/消息队列中转:运维护成本与单二进制定位冲突,否决;
- 失败即丢 + 对账补:违背「计量行是钱」,否决。

## 后果

cluster 形态增加一张本地缓冲表(迁移);续传顺序按本地自增 id,远端必须按行主键幂等(跨仓契约)。
