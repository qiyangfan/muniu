# ADR-0018:渠道余额观测与告警归属网关

- 状态:已接受(2026-10-29;openspec `provider-balance-alerting` 承载)

## 决策

上游渠道(provider)余额的**运营观测与主动告警**是网关自保能力,归属本仓数据面/管理面;与 ADR-0005 的控制面边界(租户钱包/计费/支付门户归独立控制面产品)不冲突——本能力观测的是**网关自己消费的上游账户**,不触碰租户侧的钱包语义,也不把 2xx 解释为任何人的扣款完成(data-plane-metering-sink 契约不受影响)。

1. **多源余额体系**:八种 kind(none 缺省/manual/Bearer 直查五家/云账务签名两家),注册表独立于 adapter(余额查询与协议适配是正交维度),全部纯 stdlib 手搓 HTTP/签名(与「adapter 不引厂商 SDK」同纪律)。
2. **云账务凭证**:AK/SK 只经环境变量引用注入(存名不存值),云侧最小权限(账务只读),凭证不入日志/告警/存储。
3. **余额语义**:有效余额 = 快照 − 快照后网关计量消耗(实时衰减,上游定期查询校正口径差);燃速 = 回看窗口日均已结算消耗;剩余小时 = 最小有效余额 ÷ 日均燃速,全程整数 credit 刻度。
4. **告警语义**:绝对阈值 + 剩余时间档位双规则,逐 (渠道, 规则) 持久状态机(穿越单次发射、迟滞回差、重启不重复),复用 webhook-alerting 管道发射。
5. **GCP 不纳入**:GCP 账务体系无「账户余额」API(仅预算+已消耗,小时级滞后),与本能力「余额」语义不同构;未来如立项,以独立 change 做「预算消耗观测」,复用本能力的状态机与通知管道。

## 理由

- **欠费发现从「事后」提前为「预算式」**:现状上游 402 → key 冷却 → 池降级 → 候选全失败才告警,业务已中断;网关侧已有按渠道计量(cost_credits)与告警管道,缺的只是余额观测这一块拼图。
- **边界不破**:gateway-parity design 中「渠道余额查询归控制面」指租户计费门户语境;本能力是运营观测,消费者是网关运维者自己,完整度(作品集)视角下是真实缺口而非平台功能越界。
- **诚实边界**:估算受「网关计价 ≈ 上游真实扣费」口径差影响,管理面文案一律「≈」;币种 ≠ 结算币种时禁天数估算不折算(不引汇率源)。

## 后果

- 新增 `internal/balance` 包、迁移 0015 两表、`balance` 配置节、管理 API 三端点、控制台「余额告警」页;零新增依赖。
- 未声明余额源的渠道零行为(升级零变化);余额源声明属非热更域(凭证/查询器装配期解析),变更需重启(与 auth/metrics 同口径)。
