# ADR-0002:HTTP 栈标准库优先,不引框架

- 状态:已接受(2026-09-08)

## 决策

路由用标准库 `http.ServeMux`(Go 1.22+ 的 method + wildcard pattern);中间件为约 30 行自写 chain;SSE 用 `http.Flusher` 手写转发;出站用 `net/http` 默认传输层(自定义超时/连接池参数)。**禁止引入**:gin/echo/chi/echo 类路由框架、fasthttp、自研连接池。

## 理由

- 网关的路由面极小(<15 条),框架的路由/校验/生态价值吃不到,吃到的只有依赖与魔改成本;
- 网关的价值在**转发路径的每一毫秒与每一字节**:SSE 逐事件 flush、半帧缓冲、断连传导,这些用标准库原语表达最直接,套框架反而隔一层(框架的 ResponseWriter 包装是流式 bug 高发区);
- 依赖最小化是网关的品格(ADR-0001 同源):审计面小、升级面小、面试叙事干净(「我能讲清每一行转发路径」);
- `httputil.ReverseProxy` 不用:它的整包缓冲与改写钩子模型同 SSE 逐事件转发语义不合,但实现时**参考**其 Transport/flush 细节。

## 后果

中间件/错误处理自写(30 行 ×2,可测试);Go 版本升级需关注 ServeMux pattern 语义变化(1.22+ 已稳定,风险低)。
