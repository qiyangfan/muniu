# ADR-0020:会话缓存亲和路由——健康前提下的会话粘住

- 状态:已接受(2026-11-03,openspec `session-cache-affinity`)
- 关联:ADR-0019(上游健康熔断,优先级上位)、responses-state-ownership(亲和条目归属隔离先例)

## 决策

chat/messages 两条入站 lane 增加**会话级缓存亲和**:同一会话的请求在候选循环前查亲和表,stick 候选(渠道+key)健康时置于候选序最前且池同 key 优先——保住上游厂商的前缀缓存(DeepSeek/Kimi/GLM/Anthropic 等 cache 读计价远低于全价输入)。这是一次**路由行为契约变化**:同会话从「逐请求独立 WRR」变为「健康前提下稳定命中同渠道/key」。

优先级不变式(硬边界,测试钉死):**熔断收缩 > 池冷却/禁用/欠费 > 亲和 > WRR**。亲和零新增重试、零新增候选;语义缓存命中路径零读写亲和。

worth 闸门:仅当 (渠道,key) 上次成功 attempt 的 usage 缓存读 >0 才建立粘性——无缓存证据不粘,避免把会话粘到无前缀缓存的慢源上。失败/换道立即清条;冷却/熔断让位但条目保留(恢复即复粘)。

## 理由

- 上游前缀缓存是多轮 Agent 流量最大的成本杠杆;逐请求独立 WRR 让调度自己拆缓存(会话第 N 轮大概率换 key,前缀全 miss),缓存损失随轮深线性放大。
- worth 闸门+失败即清使粘性只在「有证据、无反证」时生效,粘错(慢源/坏源)的期望代价被限制在一轮内。
- 身份解析优先客户端自报头(`X-Session-Id`,平台调用方可显式传)、缺省按 apiKeyID+首条 user 消息哈希;亲和条目绑 apiKeyID——自报头只能影响**自己 key 名下**的分组,无跨租户越权面(沿用 responses-state-ownership 先例)。

## 备选与否决

- **首条 user 消息换成首条 system**:Agent 客户端中途插改 system(TodoWrite 提醒/压缩摘要)是常态,身份不稳;首条 user 消息跨轮不变——否决。
- **stick 不可用即清条**:冷却/熔断是时间性问题,清条会丢掉恢复后的复粘;失败(真实尝试失败/换道)才清条——否决。
- **per-vendor TTL 配置面**:magpie 的 per-vendor 冷却时长是实测精调参数,零证据不建配置面;v1 固定 10 分钟 TTL,design「后续可调」登记——否决。
- **客户端钉账号头直接信任**(magpie 形态):多租户下是配额污染与越权入口——否决。

## 后果

- 路由可观测变化:同会话连续轮次稳定命中同渠道/key(metrics `muniu_cache_affinity_total{result}` 三分);控制台无需新页面(metrics 面)。
- keypool 新增带提示选中 API(`PickWithHint`,hint 不健康走既有 WRR,缺省逐字节等价)。
- responses lane 维持既有状态亲和不动;gemini/images/embeddings 不接入(无多轮会话语义或缓存收益结构不同)。

## 备选与否决(补记 2026-11-03 评审收口)

- **亲和跨优先级组越权(为缓存绕过声明降级序)**:优先级组是运营者声明的渠道策略(一等路由契约),缓存经济是次级目标——跨组越权会把健康流量经粘性拉到低优先级渠道。采纳组内 pin:降级到备用渠道时缓存连续性自然生效,作用域恰是「需要它的时刻」;spec 措辞已从「候选序最前」收窄为「stick 所在组内起点恒为 stick」。
