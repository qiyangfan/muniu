# Design

## Context

既有故障面:key 级 EMA 健康度(20 次窗口,`weight × max(0.1, 成功率)` 防饿死下限)+ 429 冷却/401 禁用;请求级 failover 判定表(首 token 前换道重放安全);渠道级无聚合健康态,唯一渠道级效果是「全 key 冷却后 `pool.Pick` 返 nil 跳过候选」(隐式且漏拍)。`all_candidates_failed` 只抓彻底失败。见 proposal.md「Why」。

## Goals / Non-Goals

**Goals:**

- 渠道级健康状态机为唯一裁决点:主动探针与被动统计都只喂它,路由只读它(候选循环一处挂接)。
- 观测面纯净:探针零触碰 key 池状态;告警与管理面复用既有管道与纪律。

**Non-Goals:**

- 不消费厂商官方状态页(自述滞后、覆盖不齐、组件映射人工;仅可作运维情报,不进路由面)。
- 不做渠道内 per-model 健康分片(probe_model 与真实流量模型不同 lane 的健康差异为登记限制)。
- 不做健康态持久化(重启重置+首轮探针校准,理由见 D4)。
- 不改 key 级 EMA/冷却/禁用语义(防饿死下限 0.1 原样保留,只在渠道层新增收缩)。

## Decisions

**D1 探针分两层:免费控制面(缺省全开)+ 付费推理面(声明制)——owner 2026-10-30 裁决。**
免费层:`GET {base_url}/models` 族(各 adapter 自声明免费端点路径,anthropic 为 `/v1/models`),证网络/TLS/鉴权/控制面服务,零货币成本,持 key 渠道缺省全开(个人项目即插即用)、渠道级 `free_probe: false` 退订。付费层:最小推理请求(max_tokens 微值),证推理面(免费端点 200 不证推理面——DeepSeek 官方状态页即按 V4 Pro / V4.1 Flash 分 lane 统计),声明 `probe_model` 即启用,不声明零付费,企业按需开。成本核算:付费层每渠道 288 次/天 × 1-token ≈ 元级/天。不校验 probe_model 是否被 model_routes 引用(模型映射有动态性),文档建议与真实流量模型一致。

**D2 探针与 key 池状态完全解耦。**
探针取 key 走 pool.Pick,但结果不写 EMA/冷却/禁用:探针流量特性(固定微值、固定频率)会污染 EMA 统计;探针 429 是「探针自身被限频」而非「key 应冷却」——判「存活但受限」维持原态,防止活渠道因探针限频被误降级;探针 401 计渠道失败但不禁 key(真实流量的 401 禁用语义不变,探针不行使处罚权)。

**D3 被动熔断缺省开启 = 路由行为变化,由 ADR 记录。**
现状:全 key 劣化渠道靠 EMA 下限 0.1 持续漏拍真实流量(key 级刻意设计)。渠道降级后候选循环整路跳过(先于 pool.Pick),漏拍终止——恢复探测职责上移到半开机制。`health.enabled: false` 完整回退到现行为。ADR 记录该变化与取舍。

**D4 状态机为进程内存态,不持久化。**
健康是短生命周期信号(降级/恢复以分钟计),持久化价值低于复杂度;重启重置 + 启动即首轮探针立即校准(启用渠道),被动统计窗口自然重建。循环纪律照 balance Service 先例:启动即评估、固定比例错峰、panic 按渠道隔离、优雅停止挂 cleanup。

**D5 恢复判据与降级原因同层对称。**
降级原因三值:控制面(免费探针阴性)/推理面(付费探针阴性)/被动(真实流量统计阴性)。恢复只由同层证据翻案:控制面降级由免费探针连续成功恢复(静默渠道的关键恢复路径——它降它翻,无须等流量);推理面降级由付费探针成功或半开真实请求恢复;被动降级只由真实流量恢复(半开期放行下一真实请求试探,成功扩回、失败回降级续期),探针成功不得解除——probe_model 与失败模型可能不同 lane,跨层解除是不诚实恢复。半开对被动渠道意味着「重新放行、下一请求即裁决」,天然无阻塞死角;对付费探针渠道半开期仍收缩,由探针裁决,不消耗真实流量。与 responses 粘性路由的「候选域收缩」既有契约(亲和渠道被收缩时的落空语义)在实现期对齐既有 requirement,不新造语义。

**D6 换道统计挂在换道决策点,豁免不计。**
候选循环「换下一候选」处计数(判定表已区分错误类与适配性豁免),按别名环形窗口聚合;最低样本数(缺省 20)防小分母误报;渠道降级引发的跳过不计换道(它不是上游信号,是本网关的处置结果)。

**D7 单候选快速失败信封。**
降级期单候选请求直接 503 `provider_circuit_open`(诚实文案:渠道熔断中,可稍后重试或配置多候选),零上游调用、零计量行(与预检闸 402 同族);多候选别名收缩跳过对用户不可见。

## Risks / Trade-offs

- [probe_model 与真实流量模型不同 lane,健康误判] → 登记限制;文档建议配置一致;后续可扩展 per-model 探针(不进本 change)。
- [被动统计在小流量渠道噪声大] → 最低样本数门槛,不足诚实不判定;探针声明制补足静默渠道的确定性信号。
- [探针消耗上游配额/计费] → 声明制 + 元级成本;429 维持原态避免探针与真实流量争抢限频窗口时误降级。
- [降级误判导致可用渠道被收缩] → 连续失败阈值(缺省 2)+ 熔断时长(缺省 300s)+ 半开快速扩回;误降级代价 = 该渠道最多 5 分钟不参与路由,可回退总开关。

## Migration Plan

新配置节 + 新包,随启动装配;缺省行为变化仅「持续失败渠道被收缩」(ADR 记录);探针声明制缺省零行为;回滚 = `health.enabled: false` 或回退二进制。
