# Design

## Context

现状(契约见 ADR-0012/0013 与 proxy-and-streaming.md):三种入站在边缘一次性翻译为 canonical chat,`messages.go` handler 直接用 canonical 字节**替换**原始请求体后进入 `handleChat`;管道内每候选经 bridgegate(`bridgeExempted`,按适配器类型判定)→ 取 key → `attempt` → `adapter.Prepare(canonical)` 出站;响应 writer 在 handler 外层包装一次,反向映射 OpenAI 形态 → 客户端协议。语义缓存指纹、插件钩子、治理判定消费 canonical;限流 gate 挂在翻译之前(messages 路由中间件链先于 handler,见原始体),直通对其零影响。约束:control 面单源不可破;`tw.committed` 不变式(已提交响应绝不二次写出/换道)是全管道基石;桥接是唯一允许改写客户端可见字段的适配器(字段改写白名单)。

## Goals / Non-Goals

**Goals:**

- 同构流量(messages × anthropic)v1 全链保真:请求零字段丢失、响应零改写,行为与客户端直连上游一致。
- 控制面(治理/缓存/限流/计量/插件/可观测)判定结果与落账口径跨路径不变。
- 与 failover 换道、bridgegate、语义缓存、插件钩子的组合语义完整且可测试(fixture 冻结)。

**Non-Goals:**

- N×M 全直译矩阵(见决策 1)。
- responses × anthropic 直译、有状态 Responses 直通(`previous_response_id`/GET 代理,见决策 9)、chat 入站经 anthropic 的桥接翻译改造(见 proposal 明确不做)。
- 新依赖(配置面仅增 `providers[].native_responses` 一项声明,见决策 9)。

## Decisions

### 决策 1:同构直通 + 既有 N+M 中转,否决 pairwise 直译矩阵

owner 的外币类比里,「直结」的真实诉求是**同币种零换译**(英镑卡在英国刷英镑),而非为每对货币各设独立牌桌。协议翻译与之不同:转换是结构性的,跨协议对(pairs)的「直译」与经 canonical 的组合翻译在结果上同构,但 pairwise 是 N×M 维护面——ADR-0003 已否决过 one-api 式 per-provider 全量复制。收益集中在同构对(保真),跨协议对保留经测试冻结的组合翻译(N+M)。故 v1 只加同构直通,翻译矩阵不动。备选「全直译矩阵」否决:维护灾难 + 零增量保真收益。

**协议平等原则(owner 2026-10-11 裁决,本变更的立法基线)**:chat 不是第一优先级协议,所有协议平等——wire 路径永远优先原生直通(同构对零翻译),翻译只属于跨协议对;canonical 在控制面的**键载体**(指纹/计数)不含语义、可替换,不构成特权;控制面的**操作表示**(参数干预/缓存体)必须逐步协议中立——本变更消除缓存侧残余(决策 6),治理/插件侧以声明制零损失保证兜底并立触发线(决策 5);不得以内部便利为由把任何同构流量降级进翻译。原生通道一律显式声明,声明粒度不同、原则同一:chat=适配器类型本身,messages=`adapter: anthropic`,responses=`native_responses`,embeddings=`EmbeddingPreparer` 能力接口。任何新增协议入仓时,同构直通通道是其立项评审的必答项。

### 决策 2:入站 handler 保留原始体,canonical 照算(双形态并存)

直通的保真目标决定了出站必须用客户端原始字节——从 canonical 重新序列化 anthropic 形态等于重走翻译,目标不成立。故 `TranslateMessagesRequest` 的 DTO 增原始体保留(与 embeddings DTO 的 `Raw` 完整持有同哲学),入站协议标签随请求传入 `handleChat`;canonical 仍计算一次,继续作为控制面单源。备选「管道内按需反解析」否决如上。chat 入站标签即「无直通增益」(基座本就透传 chat);responses 入站携带直通资格,以 provider 显式声明 `native_responses` 为前提(见决策 9),标签枚举可扩展。

连带修正(惰性拒绝):含不可翻译内容块(image 等)的请求,现行边缘 fail-fast 400 与直通目标正面冲突——多模态恰是直通要保真的对象(Claude Code 截图流量当今即被此挡死)。翻译失败降级为**失格标记**:不再即时致命,该请求跳过语义缓存(无指纹可取);路径判定落到翻译候选时升格既有 400 信封;别名不含直通候选时维持现状即时 400。备选「维持即时 400、多模态仍拒」否决:直通的头部收益被自己的翻译边界挡死,特性等于没做。

### 决策 3:直通出站走可选能力接口,不动 Adapter 五方法契约

`adapter` 包新增可选能力接口(与 `EmbeddingPreparer` 同款模式,proxy 类型断言探测):

- 直通 Prepare:原始体 + 上游 model + key → `*Outbound`(URL/鉴权头按候选既有声明,model 字段 JSON 手术改写——与 `protocol.RewriteModel` 零字段丢失同哲学);
- 流事件 meta-only 读侧:复用桥接事件机的 meta 提取(`HasContent/IsUsage/IsDone`,供首 token 判定与计量),但向客户端 passthrough 原始字节。

由 bridge 包实现。备选「给 `Prepare` 加模式参数」否决:污染全部 7 类适配器签名;备选「非流式复用 `NormalizeUsage`、流式复用事件机」即本方案读侧实际做法,仅要求 meta 与翻译字节解耦。

### 决策 4:每 attempt 路径判定 + writer 模式位

`handleChat` 持有入站标签,每 attempt 出站前判定该候选路径(native / translated),通过 writer 接口的模式位通知响应侧(直通=恒等写,翻译=现有反向映射)。判定点唯一;`tw.committed` 既有不变式保证模式切换只发生在首字节前。非流式缓冲 writer 同款模式位。备选「直通单开旁路管道(无 writer 包装)」否决:writer 还承担 metrics 追踪与错误路径职责,旁路会分裂可观测性与测试面;模式位是最小改动。

### 决策 5:回落纪律为单一决策点

路径判定函数的输入含两个回落信号:①治理对该 (provider, model) 实际产生干预(`govern` 变更集非空);②插件已改写 canonical(直通原始体过期)。任一命中即 translated,行为与本变更前逐字节一致。回落是路由决策不是错误:不计失败、不动 key 健康度,结构化日志留痕。把回落做在判定点(而非散落在 attempt 各处)保证「直通=清洁路径」的推理简单:触碰 canonical 的任何干预都使原始体失效。

**Role B 残余的裁决(owner「chat 特权」质询)**:控制面分两层——键载体(缓存指纹/TPM 估算,不含语义、载体可替换,不构成特权)与操作表示(参数干预/缓存体,改写即定 wire 形态)。后者单协议垄断正是治理回落与缓存回放两处残余的共同根:v1 消除缓存侧(决策 6 双存);治理与插件的协议中立化(约束词表/插件 ABI 按协议重建)是 ADR 级立法,v1 保留回落但给出**今天的零损失保证**——治理干预按 (provider, model) 声明制、插件按租户启用,不声明/不启用则回落永不发生,损失是运营者显式购买的。**立法触发线(写死,防悬置)**:原生对上出现真实治理/插件改写需求,或回落率可观测地非零——触发即立项,不以「未来再说」悬置。

**实现期补记(组合测试暴露,已入实现)**:治理必须对直通 wire 有裁决权——翻译器静默丢弃的参数(top_k/metadata 等)不在 canonical 中,只评 canonical 会让「drop top_k」约束在直通 wire 上失效。修正:直通 attempt 以**原始体**同规则评估治理(判定表零改动),干预即回落翻译(canonical 侧重新治理产出站请求);strict 命中仍 400 终结。约束在两条路径上等价可执行。

### 决策 6:语义缓存双存(原生体 + 协议标签 + canonical)

缓存条目双存:①canonical 形态(跨协议命中,既有回放机制与跨协议缓存等价 spec 不变);②直通原始响应体 + 入站协议标签 + 表单标记。同构命中且表单兼容时优先回放原生体(恒等,零翻译);表单不兼容或跨协议命中回退 canonical 路径(既有反向映射)。翻译失格(无 canonical)的请求跳过检索与入库,属缓存覆盖的自然边界;仅租户缓存启用才有翻译开销,翻译失败仅 canonical 侧跳过、原生体仍入库(同构命中不受影响),不阻塞主链路。备选「仅存 canonical」否决:同构回放多一次反向映射——那是控制面操作表示(Role B)单协议垄断的残余,owner 2026-10-11 裁决收编消除;备选「仅存原生体+标签」否决:chat 请求永远无法命中,破坏跨协议缓存等价 spec。

### 决策 7:bridgegate 收窄到翻译路径

多轮标记检测函数(作用于 canonical)不变;豁免判定条件从「候选是桥接型」收窄为「该 attempt 实际经翻译路径出站」。messages 入站 × anthropic 候选因此恢复工具多轮全链服务;chat 入站 × anthropic 候选边界原样保留。

### 决策 8:契约落地为 ADR-0014 + 设计文档增补

新增 `docs/adr/0014-*`(同构直通路由,记录决策 1/2/6 与否决项);`proxy-and-streaming.md` 增「同构直通」契约节(路径判定表、保真不变式、回落纪律、错误信封分域:直通透传 vs 翻译归一,两套契约按路径分域并存);`upstream-adapters.md` 增 NativePreparer 接口与读侧注记(直通不属字段改写白名单约束域——零改写);ADR-0013 补交叉引用(v1 边界被本 ADR 扩展)。

### 决策 9:Responses 原生直通采声明制;有状态粘性路由收编 v1(owner「能直连就直连」+ 学习项目框架两次裁决)

backlog「responses × OpenAI 原生直通」由 owner 指令升格入 v1。形态:`/v1/responses` 入站在边缘保留原始体(与 messages 同款),候选经 `providers[].native_responses: true` 显式声明原生 responses 能力时直通(`<base>/v1/responses`,仅 model 改写 + 鉴权注入),未声明维持既有 chat 翻译兜底;input_image 等部件经直通原生支持,经惰性拒绝机制回落翻译路径时仍按既有语义拒绝。声明制的实证依据:kongming e2e 证明百炼 responses 端点多轮工具回放四路径全 400(服务端把 `function_call_output` 翻成 `role:'tool'` 被自家老校验器拒)——「OpenAI 兼容」≠「responses 端点可用」,自动探测会让 ReAct 流量从可用倒退为不可用;声明制 = 运维知识显式化,百炼修复后翻开关即切。

**有状态收编(owner 学习项目框架裁决,2026-10-11)**:前版「无状态边缘 + 需求触发线」在项目章程(简历级工程作品,完整度即产品)下自我否决——触发条件以真实需求为燃料,而本项目明确没有需求方,该绊线构造上永不触发,「延后」即「永不」。有状态是 Responses API 的签名能力(`previous_response_id` 是它与 chat completions 的本质差异),原生 lane 拒绝它 = lane 只服务协议子集;且实证路径在仓内完备(testkit 有状态替身 + OpenAI 公开契约 fixture,双实例配方复用),「零实证冻结语义」的反对不成立。最小形态(范围 = 粘性正确性,不预建抽象):

- **provider 级亲和表**:成功响应 id → provider,进程内 TTL + LRU 容量上限;集群形态复用限流共享后端(ADR-0008 同款),未配共享则退化为实例内粘性(登记)。
- **粘性路由**:携带 `previous_response_id` 的请求候选域收缩至亲和 provider(域内 key/候选 failover 照常);跨 provider 换道对有状态请求不发生——这是服务端状态的物理约束而非实现缺陷,写进契约与文档,配指标可观测(粘性请求数/亲和命中率)。
- **GET /v1/responses/{id}**:亲和已知 → 代理转发亲和 provider 原样返回;亲和未知 → 自解释 404(既有无状态语义对未知 id 保持)。
- **缓存旁路**:状态请求上下文在服务端,指纹无意义,跳过语义缓存检索与入库。
- **翻译路径维持拒绝**:携带 `previous_response_id` 且别名无原生 responses 候选 → 400 自解释(chat 上游无服务端状态,放行必败)。
- **登记限制**:DELETE 代理 backlog;亲和随重启丢失 → 自解释降级(提示改发全量条目),文档写明。

否决记录:开关式放行(不做亲和)否决——id 定向单上游,盲发引发 404 换道级联,比显式拒绝更不诚实;「仍延后」否决——触发线在无需求方框架下不可触发,延后即永不,与章程「完整度优先」冲突。

**治理/插件 Role B 残余的同框架裁决**:不设触发线。治理协议中立化(约束 IR + 每协议 emitter)立项为姊妹变更,排入作品路线图(passthrough 落地后 propose)——它不掏空原生 lane 的承诺(不声明约束则 lane 完整工作),故不入本变更,但按「无日后」框架它必须以具名路线图项存在,而非悬置表述;插件 ABI 维持 canonical + 回落边界——理由是复杂度/收益比(沙箱 ABI 为独立契约面,协议中立插件语义的边际作品价值低,插件运行时本身已是简历项),此为显式技术选择而非需求缺失,ADR 内如实记载。

## Risks / Trade-offs

- [双形态内存驻留(原始体 + canonical)] → 既有 `maxInboundBody` 上限封顶,同量级翻倍且请求级生命周期,无跨请求驻留。
- [直通绕过翻译期拒绝,越界字段直达上游] → 直通前提即上游原生协议,字段合法性由上游裁决,与客户端直连该上游完全等价;翻译期拒绝语义只属于翻译路径(spec 已钉)。
- [writer 模式位引入状态复杂度] → 切换点唯一 + `committed` 不变式既有测试冻结;混沌/回归测试集增直通×换道组合用例。
- [缓存入库翻译开销与失败面、双存存储成本] → 仅缓存启用租户承担;双存仅直通路径条目约 ×2(原生体与 canonical 同量级);失败仅 canonical 侧跳过、原生体仍入库(降级为跨协议不可命中,不失败请求、不损同构回放)。
- [国产分支端点的 anthropic 形态差异(quirk 缺位)] → 现状桥接同样按标准 anthropic 协议出站,直通不新增风险面;差异实证后按 openai 系同款 quirk 纪律回填。
- [直通与翻译两套错误信封契约并存] → 按路径分域写入 proxy-and-streaming.md 契约节,fixture 分别冻结,防「顺手统一」破坏保真。
- [惰性拒绝使 400 时序后移(直通耗尽换道后才暴露)] → 别名级预判:不含直通候选的别名维持即时 400(与现状逐字节);含直通候选的别名上 400 仅在翻译真正被需要时出现,属诚实失败;两种时序均以契约测试冻结。
- [声明缺失导致直通能力沉睡(没人声明 = 没人直连)] → provider-presets.md 逐家标注 responses 端点可用性实证状态(百炼:多轮回放服务端缺口,勿声明;修复后开启即切);文档与验收含声明样例配置。
- [亲和表重启丢失 → 粘性断链] → 自解释降级路径(提示改发全量条目)契约化;TTL + LRU 上限防无限增长;集群复用共享后端,未配置时登记为实例内粘性。
- [有状态请求放弃跨 provider failover] → 服务端状态定向单上游的物理约束,非实现缺陷;粘性语义写进契约,粘性请求数/亲和命中率进指标可观测。

## Migration Plan

纯增量特性,新增 `providers[].native_responses` 声明(缺省 false,既有配置零改动语义不变);默认全量启用(判定确定性,无灰度开关),回滚即代码回退(行为回落翻译路径,零数据残留)。验收:协议层 fixture(直通保真逐字节断言)× proxy 组合测试(换道/缓存/治理/插件矩阵)× 真上游冒烟(Claude Code 直连 muniu → anthropic 分支端点,对拍直连上游行为;responses 直通以声明样例配置走 fixture 与假上游验收,真 key 到位前不打官方端点)。

## Open Questions

无——影响 spec、方案或任务分解的未知项均已在此前勘察与决策中闭合;分支端点形态差异属运行期实证积累,按既有 quirk 纪律处理。
