# 设计:出站面批次一

## 1. 桥接工具多轮显式边界

### 1.1 检测条件:多轮中途标记,而非 tools 声明

触发边界的是「请求消息含 `role=tool`,或任一 assistant 消息带 `tool_calls`」——即**对话已经处于工具循环中途**。仅声明 `tools` 参数的首轮请求不受影响:响应侧 `tool_use`→`tool_calls` 翻译完整,首轮合法且已服务。备选「凡带 tools 一律拒」会把声明了工具但模型未调用的单轮合法流量一并误伤,过严,否决。

### 1.2 动作语义:候选资格豁免,而非硬拒

多轮标记检出后,anthropic 桥接候选按**适配性豁免**处理——多候选别名跳过该候选继续换道,仅桥接可达(或其余候选已耗尽)时返回 400 `bridge_tool_roundtrip_unsupported` 明确信封(中文文案说明限制与替代路径)。理由:

- 符合「候选不可服务 ≠ 请求不可服务」的换道哲学:别名 [deepseek, anthropic] 携带工具流量,应经由 deepseek 服务成功,而非因一个候选的局限拒绝整个请求。
- 相比「一律立即 400」,豁免语义让边界只在其真实作用域(仅桥接可达)表现为失败;且失败形态从「上游 400 + upstream_error 冒出」变为「自解释信封」,客户端可编程处理。

### 1.3 EMA 豁免与判定表扩展

适配性豁免**不计 key EMA 失败/冷却**——这不是上游故障,是适配性不匹配;先例:adapter_missing 早退、strict 治理拒绝均不计 EMA(验收记录 18 裁决口径)。留痕:结构化日志(request_id/provider/原因),不外泄给响应(换道成功时客户端无感)。

failover 判定表是契约级:本 change 扩「候选适配性豁免(桥接工具限制)」一格,traffic-governance.md 同步,测试钉住「豁免不计失败、不触发冷却」。

## 2. Gemini 轻形态接入

### 2.1 走 OpenAI 兼容层,不写原生 adapter

Gemini 官方维护 OpenAI 兼容端点,以既有 openai 兼容 adapter + `base_url` 指向即可出站。**先真上游冒烟,记录偏差清单(字段命名/参数拒绝面/流式形态/usage 键名),quirk 只覆盖实测项**——零内置隐式知识,与 ADR-0010 声明制同哲学;文档屏蔽案(2026-09-10)的裁决先例「真上游才是权威源」直接适用。只有冒烟实证兼容层挡住必需功能时,才评估原生 generateContent adapter(预期不需要,登记为演进条件而非任务)。

### 2.2 计价与治理

- 价目:官方定价页核对后按既有价目录入(USD/百万 token;静态 YAML 兜底或运营态 `PUT /admin/v1/pricing` 均可,推荐运营态——与既有三别名一致)。
- 治理:模型参数个性走能力目录声明(如思考锁/参数黑名单,依冒烟实测),复用 ADR-0010 机制零新概念。
- fixture:从冒烟实录脱敏装配进 conformance/,钉住流式形态与 usage 键名。

### 2.3 明确不做

- 原生 generateContent adapter(兼容层够用就不维护第二协议)。
- images/audio/files(维持 backlog:国产上游多为私有异步 API,按张/按秒计价是新计量维度,当前零消费者——见 gateway-parity design 同款论证)。

## 3. 兼容承诺

边界语义只收窄「此前必败流量」的失败形态;Gemini 为纯新增 provider。既有测试零改动通过 = 回归闸门;`make check` 全绿为每任务收尾标准。
