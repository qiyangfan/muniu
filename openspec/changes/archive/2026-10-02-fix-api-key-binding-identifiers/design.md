## Context

Key 记录的 `id` 是用量 `key_id` 与控制面绑定的连接值；secret 用于鉴权，prefix 用于辨认。三者不能互换。木牛本地新签发使用 UUID，平台接入允许合法的字符串 ID，因此修复不能新增“所有 ID 必须为 UUID”的约束。

当前创建接口实际返回 `key`、`id`、`prefix`、`tenant`；列表使用 `tenant_id`。本提案如实声明创建响应，不顺手把创建字段 `tenant` 改名为 `tenant_id`。

## Decision

复用已有 ID 与已有管理入口：控制台提供复制 ID 操作，锦官绑定提示准确说明使用该值。不增加查询服务、secret 映射服务或跨控制台耦合。

### API 与类型

为 `POST /admin/v1/keys` 的成功响应补上当前真实字段的 OpenAPI schema。维护契约基线，生成客户端类型，再让创建反馈使用响应的 `id`。列表消费已有 `id`；对于兼容响应中缺失的 ID 显示“ID 不可用”并禁用复制，不能回退到 `prefix`、secret 或数组序号。

### 管理面交互

- 列表以“Key ID”明确标识真实值，长 ID 用既有截断/提示组件显示，复制时使用完整原值。
- 签发反馈在现有 secret 一次性展示旁附 Key ID；说明“锦官绑定填写 Key ID”。secret 的一次性可见规则不变。
- 复制提供成功/失败反馈；失败时保留可选中的文本供手动复制，不悄悄复制其他字段。
- CLI 的密钥列表已展示真实 ID，仅核对文案与对侧说明一致；没有缺口则不改 CLI 行为。
- 复制与显示不转换大小写、不增加 `mk-` 前缀；secret 不写入日志、持久缓存或新增浏览器存储。

### 跨仓兼容

锦官绑定 API 的字段仍是 `keyId` / `userId`，只修正操作入口的值来源。联调至少覆盖本地 UUID ID 与既有合法自定义 ID（如 `platform-key-1`）；同一 ID 必须与后续用量 `key_id` 完全相同。

## Risks and mitigation

- 混淆 ID、prefix、secret：分别标注并对复制值做组件断言，以真实计量归账验收。
- 手写响应类型漂移：先更新声明、再生成类型，保留运行时字段和创建/列表 tenant 命名差异。
- 过度限制历史 ID：不套 UUID 正则，也不对 `mk-` 做笼统拒绝。

## Validation

覆盖签发 schema 与真实响应一致、列表/签发复制准确、缺 ID 禁用及复制失败反馈；再与锦官执行真实 ID 绑定后的用量归账。使用已有 UI 组件，并执行 `make check` 和各仓契约检查。
