# 设计说明:动态价目

## Context

能力已于 2026-09-11 实现并验收(HANDOFF 验收记录 13/14);本文档固化关键取舍,供后续演进与 archive 后的主 specs 读者理解「为什么是现在这样」。

## Goals / Non-Goals

- Goals:改价零重启;峰谷价单列可表达;热路径零浮点;独立部署开箱可用(YAML 兜底)。
- Non-Goals:分布式价目广播(归控制面产品,ADR-0005);历史价目版本化审计表;逐窗全价覆盖。

## Decisions

- **倍率而非逐窗全价**:厂商错峰的真实形态是整卡折扣,一个基点数表达三段价,配置最简。
- **基点整数换算(零浮点纪律)**:倍率 ≤4 位小数即基点(万分之一),加载期一次换算各窗有效三段价(向上取整,窗口价永不低估),运行时查表——`CostWithCached` 热路径零改动。
- **固定偏移时区,不引 tzdata**:覆盖 DeepSeek(UTC)与国产家(北京时间);DST 时区应换算为 UTC 表达——单二进制零外联纪律优先。
- **先声明先匹配**:可预期 precedence,免跨午夜区间重叠判定的代数复杂度。
- **DB 覆盖 + YAML 兜底的合并**:按别名整体取代;`PricingDirectory` 原子替换(转发只读快照,在途请求旧表完成);重建遇脏数据整体失败保持旧目录。
- **选窗时机 = 落账时刻**:行内价目即该窗有效价,对账逐行可复核。

## Risks / Trade-offs

- 管理面刷新失败时持久化已生效、目录滞后 → 收敛于下次刷新/重启,日志告警(接受,概率极低)。
- YAML 行在列表中不展示窗口细节(仅缺省价)→ 管理面 PUT 即建 DB 覆盖,细节以配置文件为准(接受)。
