# webhook-alerting Specification

## Purpose
运营关键事件(key 池不可用/候选全失败/计量汇降级)的主动通知:事件→去重→退避重试→webhook,让无人值守形态下「网关出事有人知道」。

## Requirements

### Requirement: 告警通知不干扰主路径

告警发射必须 (MUST) 异步且带超时;webhook 不可达/非 2xx 必须 (MUST) 按退避重试后放弃并留日志,放弃时必须 (MUST) 将失败事实落库持久化(见投递失败自监控);必须 (MUST) NOT 阻塞、拖慢或失败化任何数据面请求;未配置 webhook_url 时告警子系统必须 (MUST) 完全关闭(零开销)。

#### Scenario: webhook 宕机请求照常

- **WHEN** webhook 端点持续不可达期间数据面请求到达
- **THEN** 请求正常服务,重试按退避进行并最终放弃留日志且失败落库

#### Scenario: 未配置零开销

- **WHEN** 配置无 alerts.webhook_url
- **THEN** 不发起任何通知行为,数据面行为与本变更前逐字节一致

### Requirement: 去重与事件覆盖

同一事件键在去重窗口内必须 (MUST) 只通知一次(窗口过期后再次发生重新通知);必须 (MUST) 覆盖三类运行时事件:候选全失败、provider key 池不可用、计量汇降级状态迁移,以及余额观测事件(余额低于绝对阈值、剩余时间穿越档位、余额源连续失败)与上游健康事件(渠道降级 `provider_degraded`、渠道恢复 `provider_recovered`、别名切换率越线 `switch_rate_exceeded`)——余额与上游健康事件由各自状态机判定触发时机并调用本管道发射;payload 必须 (MUST) 携带事件键、severity、摘要与发生时刻,余额观测与上游健康事件还必须 (MUST) 携带渠道名(切换率事件为别名)与触发上下文(余额值/剩余估算/失败计数/健康相位/换道率,按事件类型)。

#### Scenario: 去重窗口内静默

- **WHEN** 同一 provider 的 key 池不可用事件在窗口内连续发生
- **THEN** 仅首次发射 webhook,后续事件静默丢弃(不通知、不留痕)

#### Scenario: 窗口过期重新通知

- **WHEN** 同一事件键在去重窗口过期后再次发生
- **THEN** 重新发射通知

#### Scenario: 余额事件携带触发上下文

- **WHEN** 某渠道剩余估算穿越 3 天档位并发射告警
- **THEN** payload 除事件键/severity/摘要/时刻外,携带渠道名、当前有效余额与剩余估算值

#### Scenario: 健康事件携带触发上下文

- **WHEN** 某渠道探针连续失败进入降级态
- **THEN** payload 携带渠道名、健康相位与最近探针错误归类;恢复事件携带降级历时

### Requirement: 投递失败自监控

webhook 投递经退避重试仍最终失败时,失败事实必须 (MUST) 持久化(事件键、severity、摘要、最终失败时刻、错误归类),同一失败态持续期间重复失败必须 (MUST) 更新而非新增行;其后任一次投递成功必须 (MUST) 将失败态标记解除,使管理面可区分「正在失败」与「历史失败」;投递失败状态本身必须 (MUST) NOT 经 webhook 外发(通知通道已断,外发即递归);管理面必须 (MUST) 提供查询端点(纳入既有管理面鉴权与审计)并在存在未解除失败时于总览页展示警示横幅,解除后横幅消失;未配置 webhook_url 时必须 (MUST) 无任何失败记录与查询数据(子系统关闭态);事件本体不做回放——通道恢复后丢失的历史事件必须 (MUST) NOT 补发。

#### Scenario: 通道宕机失败落库

- **WHEN** webhook 端点持续不可达,某 key 池告警经退避重试后最终失败
- **THEN** 失败事实落库(事件键/severity/摘要/时刻/错误归类),管理端点可查得未解除失败态,总览页出现警示横幅

#### Scenario: 持续失败更新不新增

- **WHEN** 失败态未解除期间,第二条告警投递同样最终失败
- **THEN** 失败记录更新为最新失败事实(计数与时刻推进),不新增行

#### Scenario: 恢复成功解除

- **WHEN** 失败态未解除期间,后续任一事件投递成功(2xx)
- **THEN** 失败态标记解除,警示横幅消失;解除时刻可见,历史失败不删除

#### Scenario: 失败状态不递归外发

- **WHEN** 投递失败被记录或被解除
- **THEN** 全程不向 webhook 发起任何关于该失败状态的请求

#### Scenario: 未配置零行为

- **WHEN** 配置无 alerts.webhook_url
- **THEN** 无失败记录产生,管理端点返回关闭态,前端不渲染任何投递状态元素
