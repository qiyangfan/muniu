# pricing-time-windows Specification

## Purpose
分时段倍率:以倍率窗表达厂商峰谷价(如 DeepSeek 错峰半价),单列价目即可表达;换算在加载期一次完成,运行时零浮点查表。

## Requirements

### Requirement: 时段窗定义与匹配语义

价目必须 (MUST) 支持固定偏移时区("UTC" 或 ±HH:MM,缺省 UTC)与按声明顺序排列的倍率窗;窗为 "HH:MM-HH:MM"(终点 24:00 表示当日末;起点大于终点即跨午夜窗);匹配区间必须 (MUST) 为 [起点, 终点),按声明顺序先声明先匹配,无命中必须 (MUST) 回落缺省价。

#### Scenario: 跨午夜窗边界
- **WHEN** 配置窗 "16:30-00:30"(UTC)并分别以 16:29、16:30、23:59、00:00、00:29、00:30 请求
- **THEN** 依次为:缺省价、窗口价、窗口价、窗口价、窗口价、缺省价(起点含、终点不含)

#### Scenario: 固定偏移时区换算
- **WHEN** 配置时区 "+08:00" 与窗 "00:30-08:30",以 UTC 16:30 发起计量
- **THEN** 按本地 00:30 判定命中窗口

#### Scenario: 重叠窗先声明者赢
- **WHEN** 两个窗口覆盖同一时刻
- **THEN** 按声明顺序取第一个命中的窗

### Requirement: 倍率缩放纪律

倍率必须 (MUST) 以基点(万分之一)表示并作用于整张价目卡(三段价统一缩放);窗口有效价必须 (MUST) 为 ceil(缺省价 × 倍率)——向上取整保守计价,窗口价永不低估;溢出必须 (MUST) 报错;「cached_input 缺省同 input」的语义必须 (MUST) 在窗口内保持(0 值缩放仍为 0,由计价阶段统一解析)。

#### Scenario: 保守取整
- **WHEN** 缺省输入价 3μ、倍率 0.5
- **THEN** 窗口输入价为 2μ(向上取整)

#### Scenario: 缓存价缺省语义保持
- **WHEN** 缺省 cached_input 未配置(0=同 input)且窗口倍率 0.5
- **THEN** 窗口 cached_input 仍为 0,由计价阶段统一按「同 input(已缩放)」解析

### Requirement: 计价选窗时机

计量行落账必须 (MUST) 按请求完成时刻选窗,行内价目即该窗有效价,对账可逐行复核;窗口换算必须 (MUST) 发生在加载期,不得进入请求热路径。

#### Scenario: 端到端倍率落账
- **WHEN** 配置全天半价窗且上游返回 usage prompt=7 / completion=9(缺省价 input 2μ/tok、output 8μ/tok)
- **THEN** 计量行 cost_micro = 43(缺省价为 86)
